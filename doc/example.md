### 1.3 会话密钥协商与加解密

在密文模式下，设备首先与服务端协商（使用烧录的设备密钥0x12参与生成签名0x06）会话密钥（0x07），协商成功后的后续报文均通过会话密钥（0x07）进行AES加解密。

#### 1.3.1 设备请求会话加密参数 0x010
| 0x01 | number | 0x010 |
| ---- | ------ | ----------------------------------------------- |
| 0x01 | number | 0x010 |
| 0x02 | number | 时间戳   |
| 0x03 | number | 包流水号  |
| 0x04 | number | 1（协议版本号）            |
| 0x11 | string | 设备ID  |
| 0x12 | String | 产品ID  |
| 0x14 | bytes  | AES(plaintext = 0x02 + 0x03 + 0x11, key = 0x13) |

#### 1.3.2 服务端返回会话加密参数 0x011
| 0x01 | number | 0x011              |
| ---- | ------ | -------------------------------------------------------------------------- |
| 0x02 | number | 时间戳  |
| 0x03 | number | 包流水号 |
| 0x06 | uint8  | 1    |
| 0x15 | bytes  | 会话密钥，需解密，加密过程为：  <br>AES(plaintext = 0x02 + 0x03 + SessionKey, key = 0x13) |

#### 1.3.3 协商后报文格式
| 0x01 | number | 数据包类型，0x1XX ~ 0x4XX |
| ---- | ------ | --------------------------------------------------------------------------- |
| 0x02 | number | 时间戳   |
| 0x03 | number | 包流水号  |
| 0x11 | string | 设备ID  |
| 0x12 | String | 产品ID  |
| 0x07 | bytes  | 加密后的密文，原文内容为本文第二部分所定义的各种数据包<br><br>AES(plaintext = BKV payload, key = 0x15) |

## **3业务流程**

### 3.1 TCP连接工作流程

总体状态分为寻址、连接以及握手、数据交互这三种。

#### 3.1.1 路由寻址

设备端内置一定数量的路由服务器，设备向路由服务器查询IOT平台连接地址，根据返回的地址去连接服务端。

#### 3.1.2 连接以及握手

设备根据上一步确定的服务端地址连接服务端，连接后发送登录数据包，服务端返回登录响应数据包，若登录失败或数据包有误，设备等待根据退避算法计算出的间隔时间（**第一次连接间隔为3-10秒随机时间，第二次连接为间隔10秒，第三次以后固定每15秒重连一次**），重新连接服务端。

后台服务器（IOT平台）连接失败，每30分钟重试。

设备每小时连接（短连接）一次维护服务器（额外的维护服务器，协议一致），当后台长时间失败，维护服务器的连接周期为30分钟（提高连接频率）。**如果模组支持长连接，则使用长连接。**

#### 3.1.3 数据交互

设备定期往服务端发送心跳数据（1分钟），未收到服务端数据则主动断开，回到初始状态。

设备每10分钟上报一次位置数据和电池数据。不同运行状态下的上报频率待定。

设备可接收服务端下发的配置命令，对特定参数进行配置，并响应命令执行结果。

设备主动上报异常数据，服务端需要做出响应，不响应需要重发。

### 3.2 蓝牙工作流程

蓝牙模块作为透传通道，协议遵循主协议。蓝牙模块主要用于读取状态，设置参数，调试数据，固件升级。

蓝牙模块的设备名称为“LIERDA-XXXXXX”（XXXXXX为蓝牙MAC后六位），广播数据为蓝牙MAC + VEHICLE ID。

连接后的数据发生模式遵循主协议，即需要周期性上报状态，APP 端也可主动查询。
